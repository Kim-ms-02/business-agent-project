## 디자인 방향 (docs/design-notes.md 요약)

- 분위기: 조용한 연습실의 보면대. 살짝 푸른 회색 바탕 위에 흰 종이 한 장. 색은 칠판 초록 하나만 쓴다.
- 강조는 한 곳: 리허설 결과의 "가장 먼저 고칠 한 가지"(연한 초록 판, 굵은 왼쪽 선, 목표는 큰 글자). 코치 피드백을 점수 카드보다 위로 옮겼다.
- 질문 연습에서는 질문 글이 가장 크고, 최종 평가에서는 "이렇게 말해 보기"가 연한 초록 판이다.
- 글꼴 Pretendard 하나(OFL-1.1), 버튼 높이 44px 이상, 키보드 이동 때 초록 테두리.
- 어두운 화면을 지원한다. 글자·바탕 색 쌍의 대비는 모두 4.5:1 이상(가장 낮은 값 5.18).
- 화면 문구, 기능, 계산, 서버 코드는 바꾸지 않았다. 상태 표시는 모두 글자로도 보인다.
- 게임 같은 장식, 움직임, 아이콘은 넣지 않았다.

## 밤에 정한 것

1. 한 문장에서 여러 번 멈추면 표시 하나로 합친다("멈춤 2번, 4초·5초", 시간 순서).
2. 빠른 문장 최소 시간을 2초에서 5초로 바꿨다. 받아쓰기 시각 오차 1~2초가 2초짜리 문장에서는 50~100%가 되기 때문이다. CLAUDE.md도 맞췄다.
3. 구간별 결과는 새 서버 경로를 만들지 않고 기존 리허설 피드백 경로에 함께 보낸다.
4. 군말 수는 정확도가 낮아서 코치에게 보내지 않는다.
5. 목표의 숫자는 목표라서 "받지 않은 숫자" 검사에서 뺐다. 숫자가 있는지만 본다. 두 번 받아도 숫자가 없으면 "가장 먼저 고칠 한 가지"를 빼고 안내를 보여 준다.
6. 인용이 대본에 없으면 다시 받지 않고 노란색으로만 표시한다(v0.1과 같은 방식).
7. 받아쓰기를 켰는데 받아쓴 글이 하나도 없으면 받아쓰기를 끈 방식으로 돌아가고 "끝까지 읽었나요?"를 묻는다.
8. 받아쓰기 선택지는 웨일·오페라처럼 크롬을 바탕으로 한 다른 브라우저에서도 숨긴다.
9. "이렇게 말해 보기"에 안내가 섞이면 한 번 다시 받고, 안내가 덜 섞인 쪽을 고른다.
10. 목표 예시 베끼기는 코드 검사를 넣지 않고 SKILL만 고쳤다. 베낀 목표도 숫자가 있어 틀린 결과는 아니었다. 또 SKILL 문장을 코드에 옮겨 비교하면 "코칭 규칙은 스킬 파일 하나에" 원칙에 어긋난다.
11. 아이콘 묶음(lucide-react)은 설치하지 않았다. 버튼 글자만으로 뜻이 분명하다.
12. 리허설 결과에서 코치 피드백을 점수보다 위로 옮겼다(놓는 순서만 바뀜).

## 막힌 것, 건너뛴 것

- v0.4 7단계 검증(받아쓰기 끈 리허설과 켠 리허설에서 같은 문장 앞 5초 멈춤 비교)은 지시대로 하지 않았다.
- 화면 확인은 대부분 예시 내용으로 했다. 실제 질문·평가·리허설 결과로 본 화면은 없다(API 호출을 아끼려고). 리허설 준비 화면만 실제 앱으로 봤다.
- 받아쓰기와 말소리 측정(vad-web)이 같은 마이크를 함께 쓸 때 크롬에서 잘 도는지 보지 못했다(마이크가 필요함).
- (e) 답변에 대본에 없는 사실이 나올 때의 규칙은 시험하지 못했다.
- 잘한 점·고칠 점 목록의 번호가 화면에 보이지 않는다(전부터 그랬음). 고치지 않았다.
- 같은 방법을 3번 넘게 시도한 일은 없었다.

## 아침에 할 일

1. 화면 확인: 새 디자인을 실제로 질문 받기 → 답하기 → 최종 평가까지 해 보고, 리허설 결과도 본다. 시스템 설정을 어두운 화면·밝은 화면으로 바꿔 보고, 휴대폰 크기(375px)로도 본다. 마음에 안 드는 곳을 알려 주면 고친다.
2. 리허설 녹음 검증: 받아쓰기를 켜고 리허설을 해서 "끝까지 읽었나요?"를 묻지 않는지, 한 문장을 건너뛰면 "건너뜀", 마지막 두 문장을 안 읽으면 "읽지 않음"이 붙는지 본다. 사파리에서는 받아쓰기 선택지가 안 보이는지도 본다. 받아쓰기와 말소리 측정이 함께 잘 도는지 확인한다.
3. 시선 기준 조정: 개발용 칸으로 (ㄱ) 화면 보기 (ㄴ) 종이 대본 보기 (ㄷ) 앱 화면 대본 보기의 차이 값을 읽고 기준(15°, 0.3)을 어떻게 할지 정한다. 밤에는 바꾸지 않았다.
4. v0.4 7단계 검증: 같은 대본으로 받아쓰기를 끈 리허설과 켠 리허설을 한 번씩 하고, 두 번 다 같은 문장 앞에서 5초 멈춘다. 멈춤이 어느 문장 앞에 붙는지 비교해 prompt-log에 적는다.
5. main 합치기: 위를 확인한 뒤 테스트·타입 검사·빌드가 모두 통과하면 합친다. 아래 메시지 초안 중 고르거나 고쳐서 쓴다.
